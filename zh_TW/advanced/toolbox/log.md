# 日誌清理

![Log cleanup](/images/toolbox/log.png)

日誌清理功能用於掃描並清理系統及應用程式產生的日誌檔案，以釋放磁碟空間。在面板中它位於工具箱下的 **日誌清理** 中。

## 功能概覽

頁面頂部提供批次操作按鈕：

- **全部掃描**：掃描所有類型的日誌
- **清理全部**：清理各個已掃描日誌類型中選取的項目

掃描是隻讀操作，只會報告匹配的專案、數量和預計可釋放空間。掃描結果預設全部選取；請取消勾選需要保留的項目。清理會刪除或回收所選項目佔用的空間，並回報實際結果。如果上次掃描後又寫入了新日誌，請重新掃描。

## 日誌類型

### 面板日誌

面板執行時產生的日誌檔案。

- 點選 **掃描** 檢查日誌大小
- 點選 **清理** 刪除日誌檔案

### 排程任務日誌

排程任務執行日誌可獨立於面板執行日誌進行掃描與清理。展開結果並選擇要移除的檔案；此操作不會刪除排程任務定義。

### 網站日誌

網站的存取日誌與錯誤日誌，包括：

- 存取日誌（access.log）
- 錯誤日誌（error.log）
- 目前 Web 伺服器下各個網站的獨立日誌

:::tip 提示
網站日誌通常是佔用空間最大的日誌類型，建議定期清理。
:::

### MySQL 日誌

Percona/MySQL/MariaDB 資料庫的日誌檔案：

- 慢查詢日誌（`mysql-slow.log`）
- 二進位日誌（binlog，`mysql-bin.*`）

:::warning 注意
二進位日誌用於資料還原與主從複寫，清理前請確認不再需要。
:::

### Docker

Docker 與 Podman 相關的日誌及未使用的資源：

- 容器日誌（Docker 與 Podman）
- 未使用的映像檔
- 未使用的映像檔與容器日誌檔案分開列出；選取對應項目即可清理映像檔

### 系統日誌

系統層級的日誌檔案：

- systemd journal 日誌
- `/var/log` 下的系統日誌（`syslog`、`messages`、`auth.log`、`secure`，以及所有 `/var/log/*.log` 檔案）
- 核心日誌（`kern.log`、`dmesg`）
- 登入紀錄（`btmp`、`wtmp`）

:::tip Journal 保留
systemd journal 不會被完全刪除。清理時會執行 `journalctl --vacuum-time=1d`，因此只保留最近一天的項目。
:::

`/var/log/lastlog` 不在清理範圍內。目前的日誌檔案會被截斷清空，以便執行中的服務繼續寫入；已輪替的日誌檔案則可以移除。

## 使用方法

1. 點選各類型的 **掃描** 按鈕，檢視日誌佔用空間
2. 展開掃描結果，選擇要清理的項目
3. 點選 **清理** 按鈕刪除日誌

或者：

1. 點選 **全部掃描** 一次掃描所有日誌
2. 檢查各個類型，取消勾選需要保留的項目
3. 點選**清理全部**，清理各個類型中選取的項目

## 注意事項

1. 清理操作不可恢復，請確認日誌不再需要
2. 日誌清理涵蓋面板日誌、排程任務日誌、網站日誌、MySQL 慢查詢與二進位日誌、Docker 容器日誌與未使用的映像檔，以及系統日誌或 journal 資料。不會刪除網站內容、資料庫表、正在使用的容器卷或普通業務檔案。
3. 如果日誌可能用於故障、審計、備份失敗或安全事件調查，請先下載儲存。
4. 在正式環境中，請保留疑難排解所需的近期日誌
