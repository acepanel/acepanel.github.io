# 日志清理

![Log cleanup](/images/toolbox/log.png)

日志清理功能用于扫描和清理系统及应用产生的日志文件，以释放磁盘空间。在面板中它位于工具箱下的 **日志清理** 中。

## 功能概览

页面顶部提供批量操作按钮：

- **扫描所有**：扫描所有类型的日志
- **清理全部**：清理各个已扫描日志类型中选中的项目

扫描是只读操作，只会报告匹配的项目、数量和预计可释放空间。扫描结果默认全部选中；请取消勾选需要保留的项目。清理会删除或回收所选项目占用的空间，并报告实际结果。如果上次扫描后又写入了新日志，请重新扫描。

## 日志类型

### 面板日志

面板运行产生的日志文件。

- 点击 **扫描** 检查日志大小
- 点击 **清理** 删除日志文件

### 计划任务日志

计划任务执行日志可独立于面板运行日志进行扫描和清理。展开结果并选择要移除的文件；此操作不会删除计划任务定义。

### 网站日志

网站的访问日志和错误日志，包括：

- 访问日志（access.log）
- 错误日志（error.log）
- 当前 Web 服务器下各个网站的独立日志

:::tip 提示
网站日志通常是占用空间最大的日志类型，建议定期清理。
:::

### MySQL 日志

Percona/MySQL/MariaDB 数据库的日志文件：

- 慢查询日志（`mysql-slow.log`）
- 二进制日志（binlog，`mysql-bin.*`）

:::warning 注意
二进制日志用于数据恢复和主从复制，清理前请确认不再需要。
:::

### Docker

Docker 和 Podman 相关的日志及未使用的资源：

- 容器日志（Docker 和 Podman）
- 未使用的镜像
- 未使用的镜像与容器日志文件分开列出；选中对应项目即可清理镜像

### 系统日志

系统级别的日志文件：

- systemd journal 日志
- `/var/log` 下的系统日志（`syslog`、`messages`、`auth.log`、`secure`，以及所有 `/var/log/*.log` 文件）
- 内核日志（`kern.log`、`dmesg`）
- 登录记录（`btmp`、`wtmp`）

:::tip Journal 保留
systemd journal 不会被完全删除。清理时会执行 `journalctl --vacuum-time=1d`，因此只保留最近一天的条目。
:::

`/var/log/lastlog` 不在清理范围内。当前日志文件会被截断清空，以便运行中的服务继续写入；已轮转的日志文件则可以移除。

## 使用方法

1. 点击各类型的 **扫描** 按钮，查看日志占用空间
2. 展开扫描结果，选择要清理的项目
3. 点击 **清理** 按钮删除日志

或者：

1. 点击 **扫描所有** 一次性扫描所有日志
2. 检查各个类型，取消勾选需要保留的项目
3. 点击**清理全部**，清理各个类型中选中的项目

## 注意事项

1. 清理操作不可恢复，请确认日志不再需要
2. 日志清理涵盖面板日志、计划任务日志、网站日志、MySQL 慢查询和二进制日志、Docker 容器日志与未使用的镜像，以及系统日志或 journal 数据。不会删除网站内容、数据库表、正在使用的容器卷或普通业务文件。
3. 如果日志可能用于故障、审计、备份失败或安全事件调查，请先下载保存。
4. 在生产环境中，请保留排查问题所需的近期日志
